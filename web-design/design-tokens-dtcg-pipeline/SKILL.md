# One token file, four build targets, zero hand-edited output

A token pipeline fails in one of two ways: the JSON is a design-tool export nobody can
diff, or every platform is generated by a different person and drifts. The fix is a
DTCG file as the only source, a primitive/semantic split, and one build that emits CSS
variables, a Tailwind theme, Android XML and Swift from the same tree.

## When to Use

- Two or more platforms (web + iOS/Android) read the same brand values.
- Theme switching is being done by duplicating a stylesheet and editing hexes.
- A design tool exports tokens but developers hand-copy values into CSS.
- Component code contains `#1d4ed8` or `16px` where a semantic name should be.

## Compatibility & Stack Matrix (2026)

| Component | Version / variant | Notes |
| --- | --- | --- |
| Style Dictionary | 5.8.0 | DTCG first-class since v4; 2025.10 additions still partial in v5 |
| Node | 22.23 LTS | config must be ESM for the CLI |
| DTCG format | 2025.10 draft | `$value`, `$type`, `{alias.path}` references |
| Tailwind CSS | 4.3.5 | `@theme` is top-level only; `@theme inline` for `var()` values |
| Android | `android/resources` → `values/*.xml` | `dp`/`sp` conversion assumes rem input |
| iOS | `ios-swift/enum.swift` | requires `options.className` |

## Production Implementation

1. Install and lay out the tree: primitives and semantics in separate folders, so a
   filter can exclude raw palette values from the public API.

```bash
npm i -D style-dictionary@5
mkdir -p tokens/primitive tokens/semantic build
```

2. Author primitives in DTCG. `$type` is inherited from the group; dimensions use the
   object form, not a string.

```json
{
  "color": {
    "$type": "color",
    "brand": {
      "600": { "$value": "oklch(0.52 0.221 262)" },
      "700": { "$value": "oklch(0.44 0.187 262)" }
    }
  },
  "space": { "$type": "dimension", "2": { "$value": { "value": 8, "unit": "px" } } }
}
```

3. Author semantics as aliases only. A hex literal here is the bug this pipeline exists
   to prevent; step 8 fails the build on it.

```json
{
  "color": {
    "action": {
      "bg": { "$type": "color", "$value": "{color.brand.600}" },
      "bg-hover": { "$type": "color", "$value": "{color.brand.700}" }
    }
  }
}
```

4. Write the config as a **plain exported object**. The CLI imports it; a file that
   calls `new StyleDictionary()` throws `Cannot read properties of undefined`.

```js
export default {
  source: ["tokens/**/*.json"],
  platforms: {
    css: {
      transformGroup: "css", prefix: "ds", buildPath: "build/css/",
      files: [{ destination: "tokens.css", format: "css/variables",
                options: { selector: ":root", outputReferences: true } }],
    },
    android: {
      transformGroup: "android", buildPath: "build/android/",
      files: [{ destination: "tokens.xml", format: "android/resources" }],
    },
    ios: {
      transformGroup: "ios-swift", buildPath: "build/ios/",
      files: [{ destination: "Tokens.swift", format: "ios-swift/enum.swift",
                options: { className: "Tokens" } }],
    },
  },
};
```

5. Build. `outputReferences: true` keeps `--ds-color-action-bg` pointing at the primitive
   instead of inlining the hex a second time.

```bash
npx style-dictionary build --config sd.config.mjs
```

6. Emit the Tailwind theme from a `tw` platform (`transformGroup: "css"`, `prefix: "ds"`).
   `@theme inline` is required because the values are `var()` references.

```js
import StyleDictionary from "style-dictionary";
StyleDictionary.registerFormat({
  name: "tailwind/theme",
  format: ({ dictionary }) => {
    const lines = dictionary.allTokens.filter((t) => t.path[0] === "color" && t.path[1] !== "brand")
      .map((t) => `  --color-${t.path.slice(1).join("-")}: var(--${t.name});`);
    return `@theme inline {\n${lines.join("\n")}\n}`;
  },
});
```

7. Add theme switching as a second config with its own `source`. `source` is top-level
   only — put it inside a platform and it is silently ignored, producing an empty block.

```js
export default {
  source: ["tokens/semantic/**/*.json", "tokens/theme/dark.json"],
  platforms: {
    dark: {
      transformGroup: "css", prefix: "ds", buildPath: "build/css/",
      files: [{ destination: "dark.css", format: "css/variables",
                options: { selector: '[data-theme="dark"]', outputReferences: true } }],
    },
  },
};
```

8. Gate the build in CI: semantics may reference, never hardcode, and generated files
   must not be edited by hand.

```bash
find tokens/semantic -name '*.json' -exec grep -HnE '"\$value": *"(#|rgb|hsl|oklch)' {} +
git diff --exit-code build/css/tokens.css
```

## Failure Modes & Fixes

| Symptom | Cause | Fix |
| --- | --- | --- |
| `Unknown transformGroup "iosSwift"` | Using the enum key instead of its string value | Write `"ios-swift"` in the config |
| Swift output starts `public enum {` and will not compile | `ios-swift/enum.swift` has no default class name | Pass `options: { className: "Tokens" }` |
| Android `8px` becomes `128dp` | `android` group runs `size/remToDp`, which multiplies by 16 | Author dimensions in rem, or add an explicit `size/dp` transform |
| CLI error `reading 'log'` | Config instantiates Style Dictionary instead of exporting it | `export default { source, platforms }` for CLI; instantiate only in scripts |
| `dark.css` holds the selector but no variables | `source` set inside a platform, where it is ignored | Move `source` to the top of the second config file |
| Tailwind utilities ignore `[data-theme]` | `@theme` without `inline` re-declares the value | Use `@theme inline { --color-x: var(--ds-color-x); }` |

## Verification

- `npx style-dictionary build --config sd.config.mjs` → one `✔︎` line per destination, exit 0.
- `grep -c 'var(--ds-' build/css/tokens.css` → count equals the number of semantic
  tokens (2 in the example above), proving references survived.
- `grep -nE 'public enum [A-Za-z]' build/ios/Tokens.swift` → `public enum Tokens {`.
