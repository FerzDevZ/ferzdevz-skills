# Adopt Fabric and TurboModules without a blind upgrade

From 0.76 the New Architecture is the default, so "should we adopt it" is no
longer the question. The work is knowing which native dependencies speak Fabric,
which land on interop, and how to get back to the old renderer in one commit.

## When to Use

- Upgrading React Native to a version where `newArchEnabled` defaults to `true`.
- A screen crashes only in release with `Unimplemented component: <X>`.
- You are writing a first TurboModule, JSI host object, or Fabric component.
- Someone asks "are we on Fabric?" and the answer is a guess, not a log line.
- Skip this if the app is pinned to 0.75 on purpose and nothing requires codegen.

## Compatibility & Stack Matrix (2026)

| Component | Version / variant | Note |
| --- | --- | --- |
| React Native | 0.76+ defaults to the New Architecture; read yours with `npx react-native --version` | never trust a tutorial's version |
| Renderer | Fabric, a C++ shadow tree shared across platforms | replaces Paper |
| Native API | TurboModules generated by Codegen from a TypeScript/Flow spec | spec and module name need the `Native` prefix |
| JS ↔ native | JSI host objects, no bridge serialization | enables synchronous calls and large buffers |
| JS engine | Hermes, bundled with React Native | `global.HermesInternal` proves it |
| Flags | `newArchEnabled` (Android) and `RCT_NEW_ARCH_ENABLED` (iOS Podfile) | check before and after every upgrade |

## Production Implementation

1. Snapshot the state you are about to change.

```bash
git tag pre-newarch-$(date +%F)
grep -n 'newArchEnabled' android/gradle.properties
grep -n 'RCT_NEW_ARCH_ENABLED' ios/Podfile
```

2. Prove which renderer the shipped build uses, and log it once at boot. The
   globals below are probes, not public API: never gate features on them.

```tsx
// src/diagnostics/env.ts
export const isFabric = (): boolean =>
  (globalThis as {nativeFabricUIManager?: unknown}).nativeFabricUIManager != null;

export const isHermes = (): boolean =>
  (globalThis as {HermesInternal?: unknown}).HermesInternal != null;
```

3. Triage every native dependency before touching the version. Anything with a
   `codegenConfig` is ready; anything with only a legacy view manager lands on
   interop and is the shortlist for release-only crashes.

```js
// scripts/triage-native-deps.js  ->  node scripts/triage-native-deps.js
const fs = require('fs'), path = require('path');
const read = (dir) => { try { return JSON.parse(fs.readFileSync(path.join(dir, 'package.json'), 'utf8')); } catch { return null; } };
const dirs = fs.readdirSync('node_modules').flatMap((n) => n.startsWith('@')
  ? fs.readdirSync(path.join('node_modules', n)).map((s) => path.join(n, s)) : [n]);
const rows = dirs.map((d) => [read(path.join('node_modules', d)), d])
  .filter(([p]) => p && (p.peerDependencies || {})['react-native'])
  .map(([p, d]) => ({ dep: p.name, version: p.version, codegen: !!p.codegenConfig,
    fabricDir: fs.existsSync(path.join('node_modules', d, 'src', 'fabric')) }));
console.table(rows.filter((r) => !r.codegen || !r.fabricDir));
```

4. Turn each remaining module into a spec plus two native implementations.
   Codegen owns the interface, so the spec is the only place the contract lives.

```typescript
// specs/NativeDeviceInfo.ts
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  getBuildNumber(): string;
  isLowRamDevice(): boolean;
}

export default TurboModuleRegistry.getEnforcing<Spec>('NativeDeviceInfo');
```

```json
{
  "codegenConfig": {
    "name": "NativeDeviceInfoSpec",
    "type": "modules",
    "jsSrcsDir": "specs",
    "android": { "javaPackageName": "com.example.deviceinfo" },
    "ios": { "modulesProvider": { "NativeDeviceInfo": "RCTDeviceInfo" } }
  }
}
```

5. Run Codegen twice; the second run being a no-op proves the spec is stable and
   that nobody hand-edits generated interfaces.

```bash
cd android && ./gradlew generateCodegenArtifactsFromSchema
./gradlew generateCodegenArtifactsFromSchema
```

6. Confirm Hermes bytecode ships, not merely that the engine is present.

```bash
find node_modules -name hermesc -type f | head -1
unzip -l android/app/build/outputs/apk/release/app-release.apk | grep -E 'index.android.bundle|\.hbc'
```

7. Upgrade in one commit, then exercise release builds; interop gaps and codegen
   mismatches show up on release paths, not in Metro.

```bash
npx react-native doctor
npx react-native run-android --mode=release
```

8. Keep the rollback drilled: one flag per platform plus a clean install. If it
   takes more than one pipeline run, it is not a rollback.

```bash
# android/gradle.properties
newArchEnabled=false
```

Set `ENV['RCT_NEW_ARCH_ENABLED'] = '0'` in the `ios/Podfile` main scope, then:

```bash
cd ios && rm -rf Pods Podfile.lock && bundle exec pod install && cd ..
cd android && ./gradlew clean assembleRelease
```

## Failure Modes & Fixes

| Symptom | Cause | Fix |
| --- | --- | --- |
| `getEnforcing` throws "could not be found" | module implemented but never registered | add it to `codegenConfig.ios.modulesProvider` and the Android package list, rerun pod install |
| Release-only `Unimplemented component: <MapView>` | legacy view manager with no Fabric codegen | upgrade the library or wrap it where interop supports it; confirm with the triage script |
| Layout still jumps exactly as before | binary never left Paper; a library's `gradle.properties` overrides the flag | re-run the boot probe from step 2 against a release build |
| iOS fails with `folly/... file not found` | Pods built for the previous RN version | delete `Pods` and `Podfile.lock`, then `bundle exec pod install` on the matching release |
| Crash on dynamic code in release | Hermes runs precompiled bytecode and does not behave like JSC for runtime code generation | remove `eval`-style paths, or temporarily ship JSC while migrating |

## Verification

```bash
cd android && ./gradlew generateCodegenArtifactsFromSchema
```

- A release build logs `isFabric: true` from step 2. `false` means the flag never
  reached the binary and the upgrade is not actually done.
- The codegen task prints `BUILD SUCCESSFUL`, and a repeat run reports
  `up-to-date` for it.
- `unzip -l ...app-release.apk | grep .hbc` lists the Hermes bundle; a plain
  `index.android.bundle` means bytecode compilation was skipped.
- Rollback drill: flip both flags, clean install, confirm the probe reports `false`.
